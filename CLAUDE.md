## Build & test

```bash
# Build the project
CGO_ENABLED=0 go build -o xray -trimpath -buildvcs=false -ldflags="-s -w -buildid=" -v ./main

# Build with reproducible release flags
CGO_ENABLED=0 go build -o xray -trimpath -buildvcs=false -gcflags="all=-l=4" -ldflags="-X github.com/xtls/xray-core/core.build=REPLACE -s -w -buildid=" -v ./main

# Run all tests
go test ./...

# Run a single package's tests
go test ./proxy/vless/...

# Run a single test
go test -run TestName ./path/to/package

# Run with race detector (on selected packages — full suite is slow)
go test -race ./transport/internet/splithttp ./proxy/dns

# Run go vet
go vet ./...

# Run tests with verbose output
go test -v ./proxy/vless
```

**Note:** Some tests require external assets (`geoip.dat`) or live network dependencies (DoH, ECH tests). Tests in `app/router` (missing geoip.dat) and `infra/conf` (unknown config id: vmess) may fail in isolated environments.

**Go version:** `go 1.26` (set in `go.mod`). CI uses `^1.26.5`. The actual toolchain is `go1.26.1`.

## Project structure

This is [Xray-core](https://github.com/XTLS/Xray-core), a network proxy platform. Module: `github.com/xtls/xray-core`.

### Entry points

- `main/main.go` — CLI entry point; argument rewriting, subcommands.
- `main/run.go` — config format selection, server startup.
- `core/xray.go` — core runtime: `New`, `Start`, `Close`.
- `core/core.go` — version constants.
- `core/config.go` — config format registration and loading.

### Package layout

| Directory | Purpose |
|---|---|
| `main/` | CLI, config loading, registration (`main/distro/all/` imports all components) |
| `core/` | Instance lifecycle, config building, feature access |
| `app/` | Runtime features — dispatcher, DNS, logging, metrics, observatory, policy, proxyman, reverse portal, router, stats, version |
| `proxy/` | Protocol implementations — blackhole, DNS, dokodemo, freedom, loopback, Shadowsocks, Shadowsocks-2022, SOCKS, VLESS |
| `transport/` | Network transports — internet (TCP, TLS, REALITY, XHTTP/split HTTP, UDP, WebSocket, gRPC) and pipe (in-memory) |
| `common/` | Shared utilities — buffers (`buf`), mux, retry, crypto, cache, errors, UUID, net, protocol, session, signal, strmatcher, task, antireplay, XUDP |
| `infra/` | Configuration parsing (`conf/serial`), code formatters (`vformat`), protobuf generation (`vprotogen`) |
| `features/` | Interface definitions — DNS, extension, inbound, outbound, policy, routing, stats |

### Important note on REALITY

The `github.com/xtls/reality` module is replaced in `go.mod` with a fork:
```
replace github.com/xtls/reality => github.com/domaingts/electricity v0.1.6
```

### CI

Only one workflow exists: `.github/workflows/build.yaml` — triggered exclusively on published releases. There is no push/PR validation gate. The release uses GoReleaser (`.goreleaser.yaml`) with `GOEXPERIMENT=jsonv2`, `CGO_ENABLED=0`, and builds for `linux/amd64` (v1/v2/v3).

### Testing artifacts

- Test certificates are at `common/protocol/tls/cert/` (short-lived, auto-regenerated by `cert.Generate`).
- Some tests depend on `geoip.dat` (not bundled; `app/router` tests fail without it).
- Some tests call out to live internet services (ECH, DoH).

## Common patterns

- **Feature registration:** Components register via `common.RegisterConfig` in `init()` or via blank imports in `main/distro/all/all.go`.
- **Configuration building:** Config parsing starts in `infra/conf/serial/builder.go` (JSON via `DecodeJSONConfig`), then `config.Build()` assembles core config objects.
- **Lifecycle:** Core objects implement `common.Runnable` (Start/Close) and feature interfaces from `features/`.
- **Buffer system:** `common/buf` provides pooled 8K buffers (`buf.New()`), MultiBuffer chaining, and ownership management. Many defects in this project involve buffer ownership leaks.
- **Protocol handlers:** Follow a pattern of Validator (account management) + Server/Inbound + Client/Outbound.
- **Errors:** Use `github.com/xtls/xray-core/common/errors` package (not standard `errors`). Check `errors.LogInfo`/`errors.LogError` for diagnostic logging.

### Dependency injection

The `core.RequireFeatures` function is used to wire up feature dependencies (outbound.Manager, stats.Manager, etc.) at construction time. Features are registered as global singletons and looked up by type.

### TLS / uTLS

Standard TLS is in `transport/internet/tls/`. uTLS fingerprinting uses `UClient` and `GeneraticUClient` in `tls.go`, which wraps a *copy* of the TLS config — see `copyConfig` for which fields are preserved.
